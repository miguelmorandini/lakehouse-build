# Source Profiling Skill

This skill provides practical procedures, quantitative tests, and validation criteria for inspecting and profiling source datasets (such as `samples.bakehouse` in Databricks Free Edition) without altering data or guessing structures.

---

## When to Use This Skill

Activate this skill when:
- Exploring a new catalog, schema, table, or external file source.
- Executing Sub-stage 2 (`02_workload_and_source_profiling`) of the Assessment phase.
- Validating physical column types, null ratios, and cardinality before designing Bronze or Silver schemas.
- Testing candidate primary keys and potential foreign key join relationships.
- Investigating anomalous records, missing data, or referential integrity gaps.

---

## Step-by-Step Profiling Workflow

### 1. Catalog & Table Discovery
- Query catalog metadata to enumerate tables and views:
  ```sql
  SHOW TABLES IN samples.bakehouse;
  ```
- Inspect table metadata, storage formats, and table properties:
  ```sql
  DESCRIBE TABLE EXTENDED samples.bakehouse.<table_name>;
  ```

### 2. Physical Schema Inspection
- Extract exact column names, nullability flags, and physical data types.
- Check for naming irregularities, whitespace, special characters, or case inconsistencies.
- Record any metadata comments or column descriptions present in the catalog.

### 3. Quantitative & Statistical Profiling
For each candidate table, calculate and document:
- **Total Record Count:** `SELECT COUNT(*) FROM <table>;`
- **Column Completeness:** Absolute count and percentage of `NULL` and blank strings per column:
  ```sql
  SELECT 
    COUNT(*) AS total_rows,
    COUNT(col) AS non_null_rows,
    COUNT(*) - COUNT(col) AS null_count,
    ROUND(100.0 * (COUNT(*) - COUNT(col)) / COUNT(*), 2) AS null_percentage
  FROM <table>;
  ```
- **Cardinality & Uniqueness:** Distinct value counts per column:
  ```sql
  SELECT COUNT(DISTINCT col) AS distinct_values FROM <table>;
  ```
- **Value Ranges & Distributions:**
  - *Numeric:* `MIN(col)`, `MAX(col)`, `AVG(col)`, `STDDEV(col)`.
  - *Timestamps/Dates:* `MIN(col)`, `MAX(col)`, and date continuity checks.
  - *Categorical:* Top 10 most frequent values and outlier categories.

### 4. Empirical Key & Relationship Discovery
- **Primary Key Candidate Test:** A column is a candidate primary key **only if** distinct count equals total row count and null count is zero:
  ```sql
  SELECT 
    COUNT(*) AS total_rows,
    COUNT(DISTINCT candidate_pk) AS distinct_keys,
    COUNT(*) - COUNT(candidate_pk) AS null_keys
  FROM <table>;
  ```
- **Foreign Key Referential Integrity Test:** Test candidate join keys against the prospective parent table:
  ```sql
  SELECT 
    COUNT(child.fk_col) AS total_fk_rows,
    COUNT(parent.pk_col) AS matched_pk_rows,
    (COUNT(child.fk_col) - COUNT(parent.pk_col)) AS orphaned_rows,
    ROUND(100.0 * COUNT(parent.pk_col) / COUNT(child.fk_col), 2) AS match_rate_pct
  FROM child_table child
  LEFT JOIN parent_table parent ON child.fk_col = parent.pk_col;
  ```
- **Zero Hallucination Rule:** If `match_rate_pct < 100%`, document the orphaned records explicitly. Do not assume or assert a strict foreign key relationship without empirical proof.

## How to Validate Results

Validate the source profiling deliverables with this verification checklist:
1. **Source Authenticity:** Confirm that all reported figures (row counts, nulls, distinct counts) were generated by executing profiling queries against actual tables in Databricks, not estimated or synthetic values.
2. **Key Verification Proof:** Every proposed primary key must have an accompanying SQL assertion showing `total_rows == distinct_keys` and `null_keys == 0`.
3. **Join Validity Proof:** Every proposed table relationship must include the referential match rate and orphaned count.
4. **Deliverable Check:** Ensure profiling output is saved as structured markdown under `01_assessment/02_workload_and_source_profiling/`.

---

## Safety Controls & Free-Tier Guardrails

- **Strictly Read-Only:** Execute read queries only (`SELECT`, `DESCRIBE`, `SHOW`). Never execute `INSERT`, `UPDATE`, `DELETE`, `DROP`, or `ALTER`.
- **Query Optimization:** For tables with large row counts in Databricks Free Edition, use `TABLESAMPLE` or approximate distinct counts (`approx_count_distinct`) where appropriate to prevent memory exhaustion.
